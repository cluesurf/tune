<h3 align='center'>tune</h3>
<p align='center'>
  Three Forms
</p>

<br/>

Tune has three forms, one after another. Each one is the last one worn
down and grown out.

| | sounds | shape | what it is for |
| :--- | ---: | :--- | :--- |
| [tree](tree) | 9 | `CV` | chant, song, humming |
| [rock](rock) | 17 | `CVC` | code, generated by rule |
| [moon](moon) | 27 | `CVC` and clusters | people, hand tuned |

## Tune Tree

The first Tune.

```text
i a u

m n
p t k
h
```

**3 vowels + 6 consonants = 9 sounds**

```text
CV    CVCV    CVCVCV
```

Plus a role syllable on the end when the role is not already clear:
`ha` entity, `hi` action, `hu` feature.

```text
ma        mata        matanu
maha      mataha      matanuha
mahi      matahi      matanuhi
mahu      matahu      matanuhu
```

Every sound is one a body makes with nothing but itself. `m` and `n`
are the two hums, good and bad. `p`, `t` and `k` are the three drum
hits, lips and tongue and throat, and `k` is a rock chipped on a rock.
`h` is the breath, and in Tree it is grammar rather than vocabulary: it
carries the role and never appears in a root, so in a chanted stream
every `h` is the end of a word.

There is no compounding. Tree says one thing per word.

**2,165 roots, 8,660 words.** Tree is small enough to keep whole.

## Tune Rock

The middle Tune.

```text
i a u

m n
b d g
p t k
s z
f v
x j
```

**3 vowels + 14 consonants = 17 sounds**

Atomic form:

```text
CVC
```

Joining:

```text
CVC + CVC
-> CVCCVC
```

Rock is the algorithmic Tune. Two rules decide the atoms and four
decide the joins, and everything that survives them is in. No cycling,
no selection, no hand tuning, so no word is missing for a reason
nobody can state.

**510 atoms, 132,642 two syllable joins.** Every consonant opens 36 or
39 of the atoms and closes 36 or 39 of them, which is what a rigid
pattern buys.

## Tune Moon

The last Tune, and the one people speak.

```text
i e a o u

m n q
b d g
p t k
h
s z
f v
x j
c C
w l r y
```

**5 vowels + 22 consonants = 27 sounds**

```text
one syllable    CVC   CVCC   CCVC   CCVCC
two syllables   CVCVC   CVCCVC   CCVCVC   CVCVCC
```

Stress falls on the first syllable. Moon is Rock spoken quickly: the
unstressed vowels dropped out and the consonants that ended up beside
each other stayed there. That is where every cluster comes from, and it
is why Moon is short.

Moon is hand tuned. It is not generated, it is the lexicon people
built, six thousand terms in `tune.csv` at the root of the package.
**5,301 of 6,182 terms fit the eight shapes, 85.7%.**

## Evolution

```text
TUNE TREE
3V + 6C = 9
CV
|
|  voicing            p -> b, t -> d, k -> g
|  frication          p -> f, t -> s, k -> x
|  voiced frication   p -> v, t -> z, k -> j
|  breath lost        h -> nothing
|  final vowels fall  CVCV -> CVC
|
v
TUNE ROCK
3V + 14C = 17
CVC
|
|  vowel splitting    i -> i e, u -> u o
|  glides             m -> w, x -> y
|  back nasal         n -> q
|  liquids            d -> l, d -> r
|  weakening          k -> h
|  dental frication   s -> c, z -> C
|  unstressed vowels fall, leaving clusters
|
v
TUNE MOON
5V + 22C = 27
CVC and clusters
```

**9 -> 17 -> 27.**

Both steps are a clean partition, and both are proved on every run.
Every Rock sound has exactly one Tree ancestor. Every Moon sound has
exactly one Rock ancestor. Nothing is claimed twice and nothing is
left over.

Two things in that chain are worth pointing at.

**The three breaths are not the same sound.** Tree's `h` was grammar
and died with the role syllable. Rock has no `h` at all. Moon's `h` is
a weakened `k`. They are three separate events that happen to land on
the same letter.

**The roles doubled once.** Tree has three, marked with a whole
syllable because a bare vowel is not something Tree can say. Rock has
the same three as bare vowels, because the breath was lost. Moon has
five, because `-i` split into action and relation and `-u` split into
feature and operator, and it also has the bare root as a modifier,
which is the feature form worn down one step further.

| Tree | Rock | Moon | |
| :--- | :--- | :--- | :--- |
| `mataha` | `bata` | `bata` | entity |
| `matahi` | `bati` | `bati` | action |
| `matahu` | `batu` | `batu` | feature |
| | | `bate` | relation, from a serial action verb |
| | | `bato` | operator, from a feature word |
| | | `bat` | modifier, the feature form worn down |

## Carrying The Lexicon Back

The three lexicons are not built separately. That would let them drift.
Moon's is the real one, and the other two are worked out from it.

```text
tune.csv  ->  talk/base/lexicon.csv  ->  rock/base/ancestor.csv  ->  rock/base/ancestor.csv
   6,182            5,301                     5,276                       5,276
```

| step | what survives |
| :--- | :--- |
| `talk/code/check.ts` | 5,301 of 6,182 terms fit Moon's shapes, the other 881 go to `off-shape.csv` rather than being thrown away |
| `rock/code/fold.ts` | 5,276 of 5,301 fold back to a chain of Rock atoms, using 465 of Rock's 510 atoms |
| `rock/code/fold.ts` | all 5,276 fold back to Tree, using 69 of Tree's 170 two syllable roots |

The narrowing is the point. Nine sounds cannot hold six thousand
meanings apart. `kana` in Tree stands behind garden, spirit, count,
zero, aggregate, object and vehicle in Moon, and the splitting of the
sounds is exactly what pulled them back apart.

Every reconstruction says how much was invented, so a guess is never
read as a fact.

| mark | meaning |
| :--- | :--- |
| `held` | nothing was invented, the word was already the right shape |
| `restored` | one or two sounds were put back |
| `strained` | three or four, so the word is a guess |

## Running It

Everything runs from the package root so the `#/` import alias
resolves. Run them in this order, because each fold reads the one
before it.

```bash
pnpm --dir deck/tune exec tsx make/rock/code/calculate.ts
pnpm --dir deck/tune exec tsx make/rock/code/calculate.ts
pnpm --dir deck/tune exec tsx make/talk/code/check.ts

pnpm --dir deck/tune exec tsx make/rock/code/fold.ts
pnpm --dir deck/tune exec tsx make/rock/code/fold.ts
```

Two extra modes are worth knowing.

```bash
# write the 132,642 word join list, which is skipped by default
pnpm --dir deck/tune exec tsx make/rock/code/calculate.ts --joins

# show how one Moon word folds, before changing any rule
pnpm --dir deck/tune exec tsx make/rock/code/fold.ts --show baklax

# run the whole fold again with each rule switched off in turn
pnpm --dir deck/tune exec tsx make/rock/code/fold.ts --rules
```

## What The Rules Are Worth

Rock's rules were written down before the Moon lexicon was checked
against them, so `--rules` folds the whole lexicon again with each rule
switched off and counts the difference.

| rule off | held | invented |
| :--- | ---: | ---: |
| none, every rule on | 1,364 | 7,971 |
| atom `no-echo` | 1,539 | 7,371 |
| atom `no-voicing-pair` | 1,513 | 7,466 |
| join `no-same` | 1,403 | 7,854 |
| join `no-voicing-pair` | 1,364 | 7,971 |
| join `no-two-rubs` | 1,372 | 7,947 |
| join `voicing-agrees` | 1,618 | 7,209 |

Two findings sit in that table.

**Join `no-voicing-pair` does nothing.** Switching it off changes not
one word. Every pair it blocks is one voiced obstruent against one
voiceless one, so `voicing-agrees` already blocks all twelve. The rule
is a statement of intent, not a constraint.

**Join `voicing-agrees` is the expensive one.** It is the single rule
that forces the most invention, because Moon is full of clusters like
`kl` and `ld` that it will not allow back. It is the rule to argue
about if the folds ever need to be tighter.
